# Differentiate User-Created vs System-Generated Tasks

## Overview

Task list templates generate tasks automatically via `TemplateScheduler` → `TaskListTemplateService.generateDueTemplates()`
→ `TemplateGeneratorService.generateFromTemplate()`. These system-generated tasks are indistinguishable from
manually-created tasks in the `tasks` table, which skews the "Created vs Completed" dashboard analytics — a
recurring template that fires every Sunday at midnight creates a burst of `created_at` timestamps that were never
a deliberate user action.

This plan adds a `source` enum column (`USER` / `SYSTEM`) to `tasks`, following the existing PostgreSQL-native-enum
pattern already used for `email_tokens.token_type` (`EmailTokenType` + `PostgresEnumTypeHandler`), and threads it
through the domain model, creation call sites, and dashboard analytics filtering.

**Enum over boolean:** a boolean (`is_automated`) would need a destructive rename the moment a third source is
added (e.g. `IMPORTED`, `API`). An enum absorbs new values without migrating existing rows.

## Task 1 — Liquibase Migration

**New file:** `backend/src/main/resources/db/changelog/20260920.1-AddSourceToTasksTable.sql`

```sql
--liquibase formatted sql
--changeset mattk:20260920.1-AddSourceToTasksTable endDelimiter:go

CREATE TYPE task_source AS ENUM ('USER', 'SYSTEM');

ALTER TABLE tasks
    ADD COLUMN source task_source NOT NULL DEFAULT 'USER';

-- Index supports analytics queries that filter dashboard data by source per-user
CREATE INDEX idx_tasks_user_source ON tasks(user_id, source);
```

Picked up automatically via `<includeAll path="changelog" .../>` in `db/liquibase.xml` — no master file edit needed.

**Known limitation:** historical tasks (created before this column existed) default to `USER`, including any
that were actually template-generated in the past. There's no reliable retroactive signal to reclassify them
(`task_lists` has no back-reference to the originating template). This only affects historical data; all new
rows are correctly tagged going forward.

## Task 2 — MyBatis Generator Config

**File:** `backend/src/main/resources/mybatis-generator-config.xml`

Add a `columnOverride` to the existing `tasks` table entry, mirroring the `token_type` override used for
`email_tokens`:

```xml
<!-- Tasks Table -->
<table tableName="tasks" domainObjectName="TaskDb">
  <generatedKey column="id" sqlStatement="JDBC" identity="true"/>
  <columnOverride column="created_at" javaType="java.time.OffsetDateTime"/>
  <columnOverride column="updated_at" javaType="java.time.OffsetDateTime"/>
  <columnOverride column="completed_at" javaType="java.time.OffsetDateTime"/>

  <!-- source is a PostgreSQL enum; use a custom TypeHandler so MyBatis
       calls setObject(..., Types.OTHER) instead of setString() on writes -->
  <columnOverride column="source"
                  javaType="java.lang.String"
                  typeHandler="com.killeen.taskflow.db.typehandler.PostgresEnumTypeHandler" />
</table>
```

Since running `./gradlew mybatisGenerator` requires a live local Postgres instance, `TaskDb.java`,
`TaskDbExample.java`, and `TaskDbMapper.xml` are hand-edited to match exactly what the generator would produce
(same shape as the existing `EmailTokenDb*` generated artifacts).

## Task 6 — Set Source at Creation Call Sites

**Security note:** `CreateTaskRequest` must NOT gain a client-settable `source` field — an authenticated user
could otherwise forge analytics data by mislabeling their own tasks. The server decides based on which code
path creates the task.

**`TaskService.createTask()`** — always `USER`:

```java
Task plaintext = Task.builder()
        .userId(userId)
        .listId(request.getListId())
        .title(request.getTitle())
        .notes(request.getNotes())
        .completedAt(null)
        .dueDate(request.getDueDate())
        .subtasks(List.of())
        .position(taskPosition)
        .source(TaskSource.USER)
        .createdAt(now)
        .updatedAt(now)
        .build();
```

**`TemplateGeneratorService.generateFromTemplate()`** — always `SYSTEM`:

```java
Task task = Task.builder()
        .userId(template.getUserId())
        .listId(listId)
        .title(taskTemplate.getTitle())
        .notes(taskTemplate.getNotes())
        .completedAt(null)
        .dueDate(dueDate)
        .subtasks(List.of())
        .position((long) i)
        .source(TaskSource.SYSTEM)
        .createdAt(now)
        .updatedAt(now)
        .build();
```

## Task 7 — Analytics Filtering

**`DashboardAnalyticsConstants.java`** — new enum:

```java
public enum TaskDataSource {
    USER, SYSTEM, ALL;
}
```

**`DashboardAnalyticsRequest.java`** — new required field `sourceSelection`.

**`TaskRepository.retrieveDashboardAnalyticsTaskData()`** — new filter branch alongside the existing
status filter:

```java
TaskDataSource taskDataSource = dashboardAnalyticsRequest.getSourceSelection();
if (TaskDataSource.USER.equals(taskDataSource)) {
        criteria = criteria.andSourceEqualTo(TaskSource.USER.name());
} else if (TaskDataSource.SYSTEM.equals(taskDataSource)) {
        criteria = criteria.andSourceEqualTo(TaskSource.SYSTEM.name());
}
```
